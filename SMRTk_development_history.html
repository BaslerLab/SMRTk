This document traces every core architectural addition alongside the smaller engineering tweaks, bug fixes, security hardenings, and prompt refinements—and explains what each step enabled.

Pre-Research Edition (AI-Forge-Sandbox) — The Original Zero-Trust Sandbox, 3-Agent Split & Hierarchical Registries

🚀 Main Architectural Milestones
Hardened WSL2 Bubble, Rootless Podman Sandbox & Surgical I/O Airlock (chat_overseer.py + god_tools.py)
Designed a two-tier containment architecture: an air-gapped WSL2 Ubuntu instance (automount=false, interop=false, non-sudo agent user) launching a detached Rootless Podman container (ai-forge) over FastMCP stdio with strict kernel caps (--network=slirp4netns, --security-opt=no-new-privileges:true, --cap-drop=ALL, --cpus=4.0, --memory=16g, --pids-limit=1000, --userns=keep-id). Mounted ./my_host_input strictly read-only at /app/host_input:ro,Z and isolated each session in sessions/Session_ID_<timestamp>/.
What it enabled: Allowed the AI to freely write and execute arbitrary Python and bash scripts inside a persistent Linux workspace with zero risk of corrupting the Windows host or user source data.
Zero-Trust Host Proxy Routing (LiteLLM)
Removed all API keys and secrets from the sandbox. Configured config.py to use a dummy token (sk-sandbox-fake-key) routed through http://host.containers.internal:4000/v1, where a host-side LiteLLM proxy attached real credentials and forwarded requests to local vLLM/Ollama servers or SSH-tunneled GPUs.
What it enabled: Made credential theft from inside the container mathematically impossible.
The Foundational 3-Agent Split (Brain, Coder, Summarizer), 6 Core Tools & 2-Level Hierarchical Registries
  • The Brain (chat_overseer.py): AsyncOpenAI streaming orchestrator with prompt_toolkit ANSI CLI, context usage warnings, and 6 MCP tools (view_tool_registry, execute_bash, view_memory_registry, read_memory, compress_and_store_context, forge_and_register_tool).
  • The Coder (forge_and_register_tool): Background coding agent writing standalone Python scripts in /app/workspace/forged_tools/ with an automatic 3-attempt py_compile syntax verification loop (incrementing the random seed on each retry).
  • The Summarizer (compress_and_store_context): 2-step strict JSON schema pipeline ("strict": True) extracting deduplicated long-term Markdown memories into memories/ (Step 1) and compressing current_history.json with full backup in histories/ (Step 2).
  • 2-Level Hierarchical Registries: Organized tool_registry.json and memory_registry.json by top-level categories so the Brain browsed compact category summaries before inspecting specific tools or memories.
What it enabled: Self-expanding tool creation and long-term memory persistence without syntax errors or registry bloat overwhelming the Brain's context window.
🔧 Little Tweaks, Bug Fixes & Refinements (v1.0 → v2.1)
  • Per-Session Pixi Micro-Environments: Auto-initialized pixi init && pixi add python inside every new session directory so third-party packages stayed isolated per session.
  • Hidden <___CODER_THOUGHTS___> & <___CODER_CODE___> Stream Extraction: Intercepted and logged the Coder's full internal reasoning and code on the host terminal/log file while stripping them out before returning the tool status to the Brain.
  • Self-Healing Malformed JSON Tool Calls: Caught json.JSONDecodeError on tool call arguments and returned a structured SYSTEM ERROR tool response so the Brain automatically fixed its JSON syntax.
  • 5,000-Char Bash Output Truncation & Redirection Prompt: Truncated huge bash outputs to a 1,000-char preview and instructed the Brain to redirect output to a file (> filename.txt) and forge a Python script to parse it.
  • Self-Healing Container Reconnection Loop: Wrapped the MCP stdio client in a recovery loop catching BaseExceptionGroup and dead container drops, sweeping stale ~/.podman-run state and seamlessly reconnecting.
  • FastMCP JSON-RPC Stream Protection & Subprocess Isolation (v2.1 — 37cedbb): Added Containerfile (ENV FASTMCP_SHOW_SERVER_BANNER=0) to the repo; silenced httpx/openai/root loggers (logging.CRITICAL) to stop rogue stdout text from corrupting the FastMCP JSON-RPC stream; added stdin=subprocess.DEVNULL and start_new_session=True to execute_bash so child processes and background daemons (like Playwright) could neither steal the MCP stdin pipe nor hang the server; and raised MAX_CONTEXT_TOKENS from 32,768 to 60,000.
v1 – v2 Step 1 GPU & Scientific Stack 2-Part Active Plan Compaction VRAM Guardrails

Birth of the Research Edition — GPU Passthrough, Scientific Base Image, Bioconda & Autonomous Wake-Up

🚀 Main Architectural Milestones
NVIDIA GPU Hardware Passthrough & 50% VRAM Guardrails
Evolved AI-Forge-Sandbox into AI-Forge: Research Edition by adding --device=nvidia.com/gpu=all to Podman and enforcing strict system prompt rules capping PyTorch VRAM usage at 50% (torch.cuda.set_per_process_memory_fraction(0.5, 0)) and vLLM at --gpu-memory-utilization 0.5.
What it enabled: Hardware-accelerated deep learning, structural biology, and GPU compute inside the sandbox without starving the host's own LLM server of VRAM.
Pre-Installed Scientific, Media & Document Linux Base Image + Bioconda Channel
Upgraded Containerfile to pre-install chromium, xvfb, git, git-lfs, aria2c, jq, pigz, zstd, poppler-utils (pdftotext), tesseract-ocr, ffmpeg, graphviz, pandoc, build-essential, cmake, and gfortran, and auto-injected the bioconda channel into every session's Pixi environment. Added the "Python First" Directive (forbidding brittle awk/sed one-liners) and scientific literature API rules (Crossref, PubMed/NCBI E-utilities, Semantic Scholar).
What it enabled: Out-of-the-box bioinformatics package installation, OCR/PDF/media processing, headless browser scraping, and publication report compilation.
Hardened 2-Part Context Compaction & Autonomous Wake-Up Protocol
Prevented the Summarizer LLM from regenerating (and accidentally corrupting) the system prompt during compress_and_store_context: restricted the JSON schema strictly to ["user", "assistant"], required two structured sections in the summary (1. Current State and 2. Active Plan & Next Steps), programmatically re-injected the true config.PROMPTS["overseer_system"] at index 0, and added the WAKING UP rule so the Brain immediately resumed work after compaction without waiting for user input.
What it enabled: Zero system-prompt drift and seamless autonomous continuation across memory resets.
🔧 Little Tweaks, Bug Fixes & Refinements
  • Context Warning Threshold Tuning: Raised the context warning trigger in chat_overseer.py from 50% to 75% of MAX_CONTEXT_TOKENS (60,000) so the Brain could complete longer multi-step research chains before compacting.
  • Graceful GPU-to-CPU Prompt Fallback (v2 — 7fd031a): Added system prompt instructions so the Brain and Coder automatically fall back to CPU execution if the host lacks an NVIDIA GPU.
